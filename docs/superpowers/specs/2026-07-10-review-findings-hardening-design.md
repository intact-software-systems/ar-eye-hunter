# Review Findings Hardening Design

## Objective

Fix all thirteen confirmed findings from the review of the fourteen mainline
commits ending at `fd0f4e9`, in an isolated branch without modifying the
existing dirty `main` checkout.

## Scope And Compatibility

- Preserve existing public exports and import paths.
- Keep generic Rallar Game match support compatible for callers that do not
  opt into match identity.
- Treat browser match support as match-identity-aware because its configuration
  already requires `matchId`.
- Keep an omitted CRDT erase mode compatible with the documented optional API
  field, but reject every provided value outside the declared enum.
- Keep operational statistics response shapes unchanged while making their
  values match their names.
- Do not add unrelated refactors or deployment features.

## Architecture

The repairs are split into four independently testable tracks that share one
branch. Boundary validation and normalization live in deterministic helpers;
stateful services and workflow adapters call those helpers. Every behavioral
change starts with a regression test that fails on the reviewed baseline.

### 1. Workflow And Headless Hardening

The GitHub-free distributed workflow will no longer accept a second,
caller-selected checkout ref. It will use the exact workflow commit SHA and
place every secret-consuming hosted-agent job in the `production` environment.
The protected environment remains the authoritative branch and approval gate.

Concurrency ownership moves from the reusable phase runner to each complete
production caller workflow. All production callers use the same workflow-level
group with `cancel-in-progress: false` and `queue: max`, so complete runs queue
without prepare/operator phase interleaving or pending-run replacement. The
reusable runner no longer owns a partial-run lock.

The reusable runner will propagate prepare failures exactly as it propagates
run failures. Agent jobs cannot start after a failed rollout, SSH operation, or
marker write.

Principal-scale GitHub runs require registration. Each shard exports explicit
per-agent credentials using the globally unique agent ID as username and the
configured test password. This yields one authenticated principal per agent
instead of sharing one login across the matrix.

Headless worker logging will pass all messages through one redaction helper.
The helper removes known configured credentials and masks sensitive URL query
parameters, including navigation errors generated by Playwright. Distributed
terminal polling retries rejected network requests using the existing polling
interval and deadline; authentication failures remain fatal.

### 2. Admin And CRDT Safety

Admin lifecycle requests are parsed at runtime before repository invocation.
Only `active`, `archived`, `destroyed`, and `quarantined` are accepted. The
Postgres repository repeats the invariant defensively before creating or
updating a document, preventing invalid direct callers from persisting values.

Admin erasure accepts the documented omitted mode default, but a supplied mode
must be exactly `destroy-document` or `redact-payloads`. Invalid input fails
before audit creation or any document mutation. Route behavior remains a `400`
client response through the existing status mapping.

### 3. Match Identity And Result Contracts

`RallarGameEnvelope`, envelope creation constraints, and sequence keys gain an
optional `matchId`. `RallarGameMatchConfig` also gains an optional `matchId`.
When configured, every outbound envelope includes it and every inbound path
rejects absent or different match identity with `wrong-match`. The browser match
wrapper always passes its required `matchId`; generic callers that omit it keep
their existing wire behavior.

The public `createRallarMatchResult` overload set gains a callable overload for
the already-exported `RallarMatchResultInput<T>` union. Runtime trust checks
remain unchanged.

Match-result idempotency canonicalizes an omitted workspace and an empty
workspace to the same encoded key component, matching `GroupRef` equality and
state-scope normalization while retaining collision-safe part encoding.

### 4. Statistics And API Runner Ownership

`PSqlAdminOperationsStatsReader` receives a configurable recent-event window
with a default of fifteen minutes. Scoped and global `readState` event queries
filter `occurred_at_epoch_ms` against the injected clock and that window.
`readSystem.stateEvents` remains an all-time storage total.

Active-group counts require status `active` and either no logical expiry or an
`expiresAtEpochMs` later than the injected clock. The same rule is used by the
scoped in-memory filter and the global SQL count.

The API-v1 black-box runner will not accept an arbitrary server's `/api/config`
response. Readiness races the spawned child status, requires the child-specific
startup marker in its captured log, and only then accepts successful API probes.
An occupied port therefore fails with the child exit instead of testing the
unrelated listener.

## Finding Coverage

1. Caller-selected code with secrets: trusted workflow SHA plus protected
   environment.
2. Unknown erase mode selects destruction: strict supplied-mode validation.
3. Arbitrary lifecycle persistence: service and repository enum validation.
4. Masked prepare failure: explicit prepare failure propagation.
5. Split-phase concurrency: complete-caller shared queued lock.
6. Cross-match live traffic: envelope identity and inbound enforcement.
7. Credential-bearing navigation logs: centralized log redaction.
8. Shared principal identity: explicit per-agent registered credentials.
9. Transient polling failure: retry rejected fetches until deadline.
10. Wrong API readiness target: child status and startup-marker ownership.
11. Uncallable exported union: public union overload.
12. Split canonical idempotency key: normalized workspace component.
13. Incorrect recent and active statistics: time-window and logical-expiry
    predicates.

## Error Handling

- Invalid admin enums fail before side effects with descriptive client errors.
- Invalid or missing match identity is rejected as protocol input, not thrown
  through realtime callbacks.
- Headless authentication and authorization errors remain terminal; transient
  transport failures are observable and retryable.
- Child process exit before readiness includes exit status and captured-log
  context without allowing an unrelated HTTP listener to satisfy readiness.

## Test Strategy

- Shared/server tests prove CRDT enum rejection and no repository mutation.
- Shared-web envelope and match tests prove cross-match rejection across WS,
  RTC input, snapshot, and director-relay paths.
- Shared match tests include a compile fixture for the exported union and equal
  keys for canonical room references.
- Workflow tests parse the YAML contracts for trusted checkout, environment,
  complete-run concurrency, failure propagation, and unique credentials.
- Headless unit tests exercise whole-message redaction and rejected-fetch retry.
- API-v1 PGlite tests cover event-window boundaries and expired active groups.
- The black-box runner test uses a child/log ownership fixture and an occupied
  port regression.
- Final verification runs focused suites, package and app typechecks, workflow
  syntax validation, affected builds, and the broader unit suite when feasible.

## Completion Criteria

- Every item in the finding coverage list has a failing-before/passing-after
  regression test or an executable compile/workflow contract check.
- Focused Vitest and Deno suites pass with no failures.
- Shared, shared-web, shared-server, API-v1, shared-test, and black-box worker
  typechecks pass.
- Workflow YAML parses and its repository contract tests pass.
- The isolated branch is clean except for intentional commits, and the original
  `main` checkout retains its pre-existing user changes unchanged.
