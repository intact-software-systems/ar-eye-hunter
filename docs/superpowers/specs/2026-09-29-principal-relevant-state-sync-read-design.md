# Principal-relevant state-sync read design

**Status:** Design for maintainer review. The maintainer approved validating only groups relevant to the principal, but this document does not authorize implementation or claim a performance pass.

## Intent and boundary

Principal state-sync must continue to publish to the principal's own live sessions and the authorized live sessions of groups where that principal is an active member. The current durable reader loads and validates every group in the application/workspace twice before it identifies the actor's memberships. The controlled A-B-B-A state-write comparison failed thirteen unchanged gates, including higher serialized SQL-result bytes; the aggregate measurement does not prove that this reader is the sole cause. The read should avoid transferring unrelated group payloads while retaining the complete authorized audience and the existing conflict/reconciliation behavior.

Only a selected membership, its live group, and the children/client snapshots used for that selected audience are in this principal publication's validation boundary. An unrelated corrupt group in the same scope will no longer prevent this principal's publication. A selected corrupt member, live group, summary, session, or client remains an error, not a miss or a guessed repair. A canonical member row whose group has been purged is not selected into an audience: group rows expire while member rows may persist, and the current group-first reader already omits this case. This is the approved semantic change; it does not relax authorization or permit a process-local membership cache.

## Selected approach

Add one internal `RuntimeStateReadBatchSelector` variant, `kind: 'prefix-suffix'` with `keyPrefix` and `keySuffix`, that selects keys within a literal scope prefix and with a literal actor-member suffix. The prefix is `${groupStateScopeStorageKey(scope)}:` in `MEMBERS_NAMESPACE`; the suffix is `:member=${encodeURIComponent(principalId)}`. Both are generated by the existing canonical storage-key grammar. The SQL implementation uses the existing C-collated prefix bounds and a literal suffix comparison, not `LIKE`: encoded identifiers may contain `%` or `_`, which must never become SQL wildcards. Its result retains the current packed, caller-ordered batch shape and canonical key order. Validator, PostgreSQL/PGlite, and in-memory/fake selector consumers must agree on the new variant. This is an internal read capability, not a persisted-format change, migration, new cache, or public API alias.

`GroupStateSnapshotRepository.listSnapshotsForPrincipal` uses that selector to obtain only this actor's live member rows. It decodes each returned key canonically and validates its complete member value against the requested scope and principal before considering `status`. It then batch-reads exact group keys for active memberships and validates each live selected group against the member's decoded group reference. A missing or expired group contributes no audience, matching today's group-first read and the normal case of a group purged before its persistent member row. A present malformed or mismatched live group remains an error. Existing selected-group member, summary, and authoritative-session assembly remains the source of the full co-group audience; the caller's client snapshot read and publication proof remain unchanged.

After reading selected children, the reader performs a second actor-membership selection and exact selected-group read. It reconciles group and actor-member revisions: a newly selected or changed group/member is assembled again from durable current authority, while an unchanged selected group may use the already-read children. A group no longer selected on the second pass is excluded. This preserves late-join and concurrent-removal behavior without rereading unrelated groups. A revision conflict follows the current `StateSnapshotReadConflictError`/outer retry path; no inner retry, lock, fence, or second mutation phase is added. The selected snapshot's canonical validation and status/expiry filtering remain intact.

## Alternatives rejected for this slice

- Delaying validation until after membership selection within the two existing full-group scans changes the corruption boundary but still transfers every group payload twice. It is unlikely to address the measured byte regression.
- Scanning the existing scoped member prefix and then exact-reading selected groups avoids new SQL but transfers unrelated member payloads. It remains a fallback only if measured membership cardinality and result bytes show that cost is acceptable.
- Adding a principal-membership index or persisted projection now is unjustified. The existing `(store_namespace, store_key COLLATE "C")` index bounds the scope scan, while the suffix predicate's cost must be measured on representative data. An additive index is a separate measured decision only if the unchanged gate and query plan demonstrate need; no data migration or dual-read path is proposed.

## Failure and observability contracts

The descriptor validator rejects malformed selectors. SQL and in-memory selector implementations filter by namespace, literal prefix, and literal suffix; the packed-result validator checks selector association, key bounds, duplicates, and ordering. Batch results do not carry a namespace or know the group-state key grammar, so the group-state repository decodes selected keys canonically and rejects wrong-scope or wrong-principal keys and values. An expired selected row is resolved by the existing live batch reader, not returned as authority. Database read failures and concurrent revision conflicts propagate through the existing AppInbox/QueueBox owner; they are not converted to empty audiences. Query-level diagnostics may report bounded operation counts, result bytes, and duration, but must not use principal/group/session identifiers as metric labels or log full payloads.

## Verification and decision gate

Write behavior-first tests for the same full authorized audience; unrelated corrupt group tolerated; selected corrupt live member/group/child/client rejected; persistent active member with a purged group omitted; inactive, expired, wrong-scope, and replaced sessions excluded; and late join/removal or revision change reconciled. Cover literal suffixes with percent, underscore, colon, Unicode, and prefix-lookalike identifiers in the batch selector's memory, PGlite, and PostgreSQL paths. Preserve dense caller order and C-order results. Run focused group/client/state-sync tests, package and API typechecks, real PostgreSQL integration, the unchanged medium-scale three-process correctness gate, and the existing state-write A-B-B-A comparison. Capture a representative `EXPLAIN (ANALYZE, BUFFERS)` and per-query result bytes before considering an index. The performance fix is accepted only if the unchanged comparator passes without weakening workload or gates, or is reported as still failing with the remaining measured cause.

For every changed human-authored file, review and remediate that file in full; every support file changed by remediation joins the closure recursively. Independent untouched code stays outside it. Remove affected unused/legacy code rather than preserving it by default. Any public compatibility or migration decision requires separate explicit approval.
