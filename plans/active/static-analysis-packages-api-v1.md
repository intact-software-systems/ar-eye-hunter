# Static analysis: packages and api-v1

Static only. No runtime profile, no EXPLAIN, no code change. Wall-clock cost, row counts, and heap versus index-only plans are uncaptured unless the query shape itself proves the work.

Scanned at `ee510bbb`. Scope: production TypeScript under `packages/**` and `apps/api-v1/**`. Tests were excluded by the repo style checker's production filter. `packages/shared-test` and `packages/shared-rtc-bench` are called out when a count includes them.

## Executive summary

The tree is already under a real static gate, and that gate is mostly clean on the rules it blocks. Transaction-write check passed with 57 advisory unresolved-callback rows and zero blocking findings. Cognitive load on 1,574 product files is one file at the refactor tier, nine at review, and forty at warning.

The expensive findings are request-path scans the current checkers do not look for:

1. Every RTC RTT policy read loads every presence session in the deployment, then keeps the two session ids it needed.
2. A non-idempotent client mutation range-scans every membership row in the workspace. An idempotent replay loads that principal's entire event history to find one event id.
3. Every CRDT mutation, including append, computes `sum(octet_length(snapshot_envelope)) over ()` and then `limit 1`. PostgreSQL evaluates the window before `LIMIT`, so every snapshot body for the document is measured to return one row.

Style debt a checker can already see, and that is worth gating for new code: 134 product functions over the 60-line standard, two CRDT files over the 1,200-line backstop, and one graph file at cognitive load 404. `function.length` is specified in the repo standard and is not implemented in the checker. `dprint` and `deno lint` are not steps in Release Gate.

## Hot path map

- Client mutation HTTP/AppInbox → `readClientMutation` → either `listSnapshotsForPrincipal` (workspace membership range, then each group's members and sessions) or `listEvents().find` (full event history).
- RTT AppInbox → `readPolicyInputs` in `create-api-v1-topology-services.ts` → `listAllPresenceSessions` → `findAllEntries(SESSIONS_NAMESPACE)` (full namespace `SELECT`, no `LIMIT`).
- CRDT append/admin → `PSqlCrdtMutationRepository.readMutation` → `readSnapshot` window aggregate. The log repository's `readSnapshot` uses the same query.
- Login and state-API rate limit → `readRateLimiter` → process-wide `LatestRepository` with TTL and no `maxEntries`. Login keys can come from forwarded headers.
- WebSocket broadcast encodes once (`JsonWebSocketServer.broadcast`). Per-message payload rejection UTF-8-encodes `payload.resource` on the router path. That cost is linear in payload size and is secondary to the scans above.

## CI checkers worth adding

Yes. Several practices are mechanical, local, and low-noise. Others are already specified and only missing from the scanner.

Add these:

1. **`function.length` inside `scripts/repo-style-check`.** The thresholds already exist (warn >40, review >50, fail-the-standard >60). Emit the rule the same way `file.length` is emitted. The changed-range gate then rejects new or worsened functions without failing the repo on the existing 134. Exempt a function whose body is one template-literal SQL statement, or the guarded-batch writer becomes a permanent exception the day it is touched.
2. **`npm run format:check` on the static lane.** `dprint` is the only formatter and no workflow invokes it. Run it once on `main` first. If the tree is dirty, a formatting commit belongs in `.git-blame-ignore-revs` before the check becomes blocking.
3. **`deno lint` beside `deno task check` for the Deno apps.** Root `deno.json` already includes `apps/api-v1` with the recommended tag. Release Gate runs `deno check` only. Deno was not installed in this environment, so the current lint result is uncaptured. Run it before making the step blocking.
4. **A narrow SQL shape check** next to the transaction-write checker, for authored `sql` templates under `packages/**` and `apps/api-v1/src/**`:
   - Window aggregate (`over ()`) in the same statement level as `limit`. The two CRDT snapshot queries are the current hits.
   - `findAllEntries(` and `listAll*Sessions` / `readAllPSql*EventRows` referenced from a mutation `read` function. Allow the expiry sweep and admin list pages that already have a paged twin.
5. **`process.env` / `Deno.env.get` outside an allowlist** of composition roots, test support, and `packages/shared-test`. Product code is already clean, so the check protects the boundary the standard describes.

Leave these as warnings or human review:

- Full-repo `boundary.unknown`, `function.input-contract`, and cognitive-load tiers. New growth is already blocked. Turning the corpus red does not make the 528 unknown rows actionable.
- `no-await-in-loop`. A body-level heuristic marked 179 functions that contain both a loop and `await`. Many are sequential startup and artifact writers. The real N+1s above are full-collection reads, which a loop lint misses.
- `console.*`, banned verbs (`handle`, `process`, `execute`), and plain-object `type` aliases. The opt-in object-interface scan added 79 rows. The standard already calls that signal noisy.
- Navigation details. The full report prints and exits 0. High-confidence registration indirection already fails the changed-range gate.

## False-positive risks

- The expiry sweep and admin `listPublicationEntries` / `listMeasurementEntries` are full namespace reads on purpose. A checker that flags every `findAllEntries` will drown the RTT misuse unless it is rooted at mutation `read` functions.
- `writeRuntimeStateGuardedBatch` will trip a naive line-count rule.
- `prune-graph.ts` will trip cognitive load. Splitting the k-best-links algorithm into pass-through files makes it harder to follow.
- Prefix scans that use `store_key >= prefix AND store_key < prefixEnd` can be index range scans. The membership finding is the extra `right()` filter on a workspace-wide prefix, not the existence of prefix queries.
- Rate-limit cardinality depends on whether a proxy rewrites forwarded headers. The code accepts the header either way.
- `listEvents` on the idempotent path runs only when a stored receipt has an event id. The query is still unbounded when it runs.

## Plan

Two slices are enough to start. The rest waits on their results.

### Slice A — Stop the three full reads

Owner: `packages/shared-server` client-state mutation, group-state session reads, and the api-v1 topology composition that calls them. CRDT snapshot SQL is the third edit, in `psql-crdt-mutation-repository.ts` and `psql-crdt-log-repository.ts`.

1. RTT: resolve the two session ids without `listAllPresenceSessions`. Leave the expiry sweep on the full read.
2. Client replay: point-read the receipt event. Client first write: select that principal's memberships without a workspace-wide `right()` filter.
3. CRDT: drop the window aggregate. Read `snapshot_count` from `crdt_documents`. Persist snapshot bytes on the document row if quota checks still need them.

Acceptance: the three SQL shapes are gone; focused repository tests cover the new lookup; EXPLAIN on a seeded fixture shows the RTT and snapshot plans independent of unrelated rows. If slice A changes the client or CRDT mutation read path, run the state-write comparative perf gate and the medium-scale black-box gate. No public HTTP shape change is required.

### Slice B — Teach CI the rules it already believes

1. Emit `function.length` from `scripts/repo-style-check`, with the SQL-template exemption, and cover it in `packages/tests/repo/repo-style-changed-check.test.ts`. Existing functions stay warning-only. New or worsened ones fail `check:repo-style:changed`.
2. Run `npm run format:check` locally. If it is clean, add it to the Release Gate `checks` job. If it is not, format in one commit listed in `.git-blame-ignore-revs`, then add the check.
3. Run `deno lint` in `apps/api-v1`. If it is clean, call it from the existing Deno check step.
4. Add the window-plus-`limit` SQL rule beside `check:transaction-writes`, with the two CRDT queries as the fixture that fails before the fix and passes after slice A.

Out of this plan: a repo-wide split of CRDT files, `prune-graph.ts`, or route registrars. Touched-file closure already requires that when those files change. A campaign to delete `console.*` or to fail the build on all 528 `boundary.unknown` rows is not worth the noise.
