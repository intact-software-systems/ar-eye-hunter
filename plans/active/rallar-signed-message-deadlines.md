# Signed message deadlines implementation plan

**Decision requested.** Approve a source-breaking, single-cutover replacement of the five positional AL message builders with named inputs, plus connection-scoped timing through final browser delivery. Approval covers slice 1 of the [shared-time product plan](rallar-shared-time.md). [Issue #836](https://github.com/intact-software-systems/ar-eye-hunter/issues/836) owns the broader recovery and qualification work.

**Customer outcome.** A short-lived signed message sent between two browsers whose device clocks disagree arrives while valid. A delayed delivery attempt is refused when the latest plausible server time reaches the signed deadline. Forwarding, WebSocket fallback and replay cannot extend its lifetime. Wide clock uncertainty can shorten the usable delivery window. The wire format, TTL policy, and signature inputs retain their existing semantics.

## Ownership and constraints

- Shared TypeScript owns envelope construction, proof verification and deadline rules. Browser composition supplies the connection lifetime and calibrated epoch. Apps use the existing messaging facade. Keep game rules, presence leases, durable checkpoint timing, and public clock or timeline APIs outside this slice.
- Use the existing `readBrowserServerCreationEpochMs` and `readBrowserServerExpiryEpochMs` readers and the owning AL admission and lifecycle policies. Each has a different job. Reuse the shared comparison at each equivalent decision. Avoid a second sampler, transport-specific TTL arithmetic, or a second envelope for fallback.
- Replace the low-level builder signatures and their callers together. Delete positional paths outright. No compatibility overload, migration adapter, dual wire reader, legacy registry entry, or implicit wall-clock default. Consumers outside the repository would need the new source API on upgrade. Approval of this plan authorizes that breaking decision for these five builders only.
- Review and remediate every changed human-authored file in full. Include each support file changed by remediation recursively. Independent untouched code remains outside closure. Apply the repository standards to test fixtures as well as runtime code.
